# Stavka audit — 2026-09-05

Scope: all active Stavka applications, services, packages, and tools. Other
repositories and real Arma execution were excluded. The starting revision was
`51a5d462b842bb96248186c605c0c5dcefc4290f`; pre-existing provider-owner changes
were preserved. The user subsequently authorized committing, pushing, and
production deployment and local development with their subscription accounts;
the release and live verification are recorded below.

## Findings and changes

1. **Inference configuration failed after its first read.** The repository saved
   an alias array but decoded it as a whole configuration. Reads now construct
   the configuration from the actual SQLite columns. A real SQLite round-trip
   test covers save, reload through another repository instance, and update.
2. **Forged routing headers could survive filtering.** Deleting from a live
   `Headers.keys()` iterator skipped adjacent entries. Filtering now iterates a
   snapshot. The runtime test executes forwarding, checks removed credentials
   and forged metadata, and verifies response-derived usage persistence.
3. **Simulation work allocated and recalculated unnecessarily.** Movement only
   needs to know whether a detected enemy is within 80 metres; an early-exit
   scan replaces filter/reduce/nearest selection. Combat computes range once
   per pair and creates pair keys without allocating/sorting arrays. Removed
   `readyGroup`, which only forwarded to `spawnGroup`.
   Browser debugging also found a render loop after simulation reload: copying
   table data/columns on each render repeatedly triggered TanStack resets.
   Memoized inputs now preserve identity until the actual data changes.
4. **Several app routes were placeholders.** System and model pages read private
   binding metadata. Decisions and usage read canonical session exports; hosted
   simulations link to faction-specific sessions. Access shows organization
   membership. Routes preserve Access verification and upstream error status.
   Missing-session exports now return 404 before querying an uninitialized
   Durable Object database, with route and browser regression coverage.
5. **Source-text tests gave false layout assurance.** Removed four viewport
   source-inspection test files and routing-metadata string checks. Browser
   checks found clipped nested simulation panes and a mobile inference pane
   whose fixed height assumed an unwrapped header. Flex sizing fixes both.
   Visual checks also exposed a 150-pixel canvas inside a taller battlefield
   panel and overlapping mobile grid rows that blocked Step clicks. Explicit
   canvas height and a mobile flex column fix those defects.
   Genuine dependency, SQL-boundary, and framework architecture checks remain;
   their source inventory now includes `services/`.
6. **Deployment drifted from the engineering contract.** Automatic CI deployment
   was removed. The separate manual workflow is main-only, uses `production`,
   and deploys exactly inference, Commander, and the app. The already-live
   `stavka.sands.red` custom-domain route is declared in app configuration.
7. **Local acceptance needed manual setup.** `pnpm verify` coordinates fresh
   checks and browser acceptance; `pnpm qa` and `pnpm qa:serve` provide a
   credential-free, isolated local stack with worktree-specific ports and
   failure traces. See [the workflow](../AGENT_WORKFLOW.md).

model execution. The user's production screenshot exposed an empty battlefield
and disabled controls. The follow-up replaces the app shell with grouped
sidebar navigation, data-backed overview cards, a compact simulation workspace,
readable mobile unit markers, fitted 2D/3D cameras, and bounded replay panes.

account service. Missing/invalid memberships and machine credentials fail

run automatically. A successful direct test is not full simulation evidence.

[remaining work](../REMAINING_WORK.md). The previous screenshot PDF contains
local fixture results and is superseded as evidence of production operation.
